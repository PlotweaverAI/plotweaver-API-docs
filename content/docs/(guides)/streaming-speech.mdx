---
title: "Streaming speech"
description: "Audio that starts playing in about 0.1 seconds, for live calls and voice agents."
---

`POST /v1/speech/stream` takes the same JSON body as [`POST /v1/speech`](/text-to-speech) and sends raw audio back while it is still being generated. Use it whenever someone is waiting to hear a reply: phone agents, voice assistants, read-aloud buttons.

<Info>
Streaming covers the five Nigerian languages (`yo`, `ha`, `ig`, `pcm`, `en`), with a built-in voice or a voice you cloned in a Nigerian language.
</Info>

## Audio format

Raw PCM, sent as it is generated:

| | |
|---|---|
| Encoding | Signed 16-bit little-endian (`X-Audio-Format: pcm_s16le`) |
| Channels | Mono |
| Sample rate | 24,000 Hz (`X-Sample-Rate: 24000`) |

Leading silence is trimmed, so the first bytes you receive are speech.

## Try it

Pipe the stream straight into a player:

```bash
curl -sN -X POST https://api.plotweaver.app/v1/speech/stream \
  -H "X-API-Key: $PLOTWEAVER_API_KEY" -H "Content-Type: application/json" \
  -d '{"text": "Ẹ ṣé gan-an fún ìpè yín. Báwo ni mo ṣe lè ràn yín lọ́wọ́?", "language": "yo"}' \
  | ffplay -autoexit -nodisp -f s16le -ar 24000 -ac 1 -i pipe:0
```

## In your code


```python tab="Python"
import os
import requests

with requests.post(
    "https://api.plotweaver.app/v1/speech/stream",
    headers={"X-API-Key": os.environ["PLOTWEAVER_API_KEY"]},
    json={"text": "How far? I fit help you today?", "language": "pcm", "voice_id": "tega"},
    stream=True,
    timeout=120,
) as r:
    r.raise_for_status()
    for chunk in r.iter_content(chunk_size=4800):  # 100 ms of audio
        play(chunk)  # hand each chunk to your audio output or call
```

```javascript tab="Node.js"
const res = await fetch("https://api.plotweaver.app/v1/speech/stream", {
  method: "POST",
  headers: { "X-API-Key": process.env.PLOTWEAVER_API_KEY, "Content-Type": "application/json" },
  body: JSON.stringify({ text: "How far? I fit help you today?", language: "pcm", voice_id: "tega" }),
});
for await (const chunk of res.body) {
  play(chunk); // 16-bit PCM, mono, 24 kHz
}
```


## Speed or quality

| `mode` | Engine | First audio | When to use |
|---|---|---|---|
| `speed` (default for streaming) | STORM Gust 1.0 | About 0.1 s | Live conversation, where every millisecond counts |
| `quality` | STORM v1.5 | A little later | Read-aloud and announcements, where expression matters most |

Send `"mode": "quality"` (or pin `"model": "storm-v1"`) to stream a built-in voice on STORM v1.5. The `X-Model` header tells you which engine answered.

## Capacity and overflow

Each account can run up to **12 requests at once with built-in voices** and **8 with cloned voices**, counting streams and `POST /v1/speech` together.

When STORM v1.5 is busy, a request with a built-in voice is served by STORM Gust with the same voice instead of waiting (`X-Model: storm-gust`, `X-Overflow: true`). Only when both are full does a new request get `429` with a `Retry-After` header, straight away rather than after waiting in a queue.

## Billing a stream

Once audio has started, the whole text is billed, including when you close the stream early (for example when a caller interrupts). A stream that fails before any audio, or because of an error on our side, is not billed.

<Tip>
For live calls, send **one sentence per request**. Your agent starts speaking sooner, and if the caller interrupts, only that sentence is billed.
</Tip>

A streamed take cannot be retried halfway through, so prefer `POST /v1/speech` when quality matters more than latency, for example for pre-recorded prompts.
